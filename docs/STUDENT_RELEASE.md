실제 조치 집행 연결과 외부 시스템 확인이 미완료이므로 전체 운영 완료로 표시하지 않는다.

## 3. 이동 가능한 실행 절차

아래 경로 이름은 새로 만들 검사 폴더의 예시다.
원래 프로젝트 밖의 상위 작업 폴더에서 PowerShell을 열고, 대상 폴더가 없음을 먼저 확인한다.
이미 있는 폴더를 덮어쓰지 않는다.

1. git clone --branch r5-deploy --single-branch https://github.com/Soyoon0608/aleph-defense-starter.git keshev-defense-stage22-check
2. cd .\keshev-defense-stage22-check
3. git switch --detach <제출할 실제 40자리 커밋>
4. git rev-parse HEAD로 대상 커밋과 일치하는지 확인한다.
5. git status --short가 비어 있는지 확인한다.
6. cd .\on-client
7. node --version 및 node --check .\student\extension.mjs를 실행한다.
8. 사용할 포트가 비었는지 확인한다.
9. powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo -Port 5190
10. http://127.0.0.1:5190/ 에서 예제 표시와 학생 영역을 확인한다.

꺾쇠의 커밋 표시는 그대로 실행할 명령이 아니다. 최종 제출 화면에 넣는 실제 커밋으로 바꾼다.
예제 실행에는 외부 npm 의존성 설치와 개인 인증 설정 복사가 필요하지 않다.
on-client에는 lock 파일이 없으며, 루트 package-lock.json을 학생 앱의 설치 목록으로 사용하지 않는다.
기본 예제 실행과 세부 장애 안내는 STUDENT_RUNBOOK.md를 함께 읽는다.
문서에 적힌 기존 절대경로는 관찰 당시 위치 기록이며, 프로그램이 그 경로를 요구하는 것은 아니다.

## 7. 미완료 사항과 인수인계

현재 기록은 같은 PC의 별도 폴더에서 예제 앱을 실행한 학생 진술이다.
실제 SDP·XDR 연결, AI 사건 설명, OSV 외부 조회, 조치 집행·효과 확인은 미확인이다.
기존 제공 코드와 학생 표시 코드, 실제 외부 연결을 서로 구분한다.
로컬 실행 성공과 공식 AI 원문 검토 통과도 별개다.
최종 제출본은 아래 8절의 확인 커밋과 실행 파일을 대조한다. 문서만 바뀐 경우에도 커밋 해시와 실제 실행 확인을 구분한다.
이후 코드가 바뀌면 변경한 커밋을 기준으로 다시 검토하고, 영향을 받는 확인을 재실행한다.

- 제공 실행 도구의 서버 응답 확인·주소 안내 메시지를 확인했다.

제출본의 실행 파일이 위 확인본과 같은지 비교하고 검사 폴더를 제출 커밋으로 맞춘 뒤 마지막 시작·화면 확인을 진행한다.
비교 명령: git diff --exit-code e938b98f3840d19b4228b0536e4bbcecfd15405d HEAD -- on-client src api scripts package.json package-lock.json .env.example .gitignore
차이가 있으면 위 결과를 변경된 실행 코드의 결과로 대신하지 않는다.
외부 연결·실제 조치·다른 PC 재현은 계속 미확인이다.
